
리눅스 기초 학습 2
======

본 내용은 Dreamhack의 Linux 201를 학습하고 정리해봤다. 학습 내용을 정리하고 추가로 이해한 내용을 덧붙여 작성했다.

패키지
------
: 소프트웨어를 실행하기 위한 모든 파일들의 집합 (실행파일, 설정파일, 라이브러리 등도 포함됨)
하지만 관리해야할 패키지가 많아지면 사용자가 모두 파악하는게 어려워 패키지 매니저를 사용한다.
사용자가 원하는 프로그램을 원활하게 설치하고 실행하려면 관련 명령어들을 잘 사용할 수 있어야 한다.

**리눅스 패키지** 
: 리눅스에서 프로그램을 실행하기 위해 필요한 파일들의 집합
* **소스 패키지**: 소스 코드가 들어있는 패키지
  * 장점: 사용자가 소스코드를 자유롭게 변경하여 원하는 형태로 프로그램 개조 가능
  * 단점: 설치 시간이 긺, 컴파일 과정 중 오류가 발생할 수 있음
* **바이너리 패키지**: 소스 패키지 컴파일 작업이 성공적으로 끝난 바이너리 파일들이 들어있는 패키지
  * 장점: 설치 시간이 짧음, 오류 발생 확률이 낮음
  * 단점: 패키지 의존성이 있음 (컴파일 된 바이너리가 필요로 하는 의존성 파일들을 제대로 제공하지 않는 경우 오류 발생)
    > 패키지 관리자를 사용하면 대부분 문제없이 설치 가능
    
**패키지 관리자**
보통 2가지로 나뉜다.
* **저수준 패키지 관리 도구**: 단순히 자신의 패키지를 설치, 제거할 목적으로 사용되며 패키지 간 의존성 고려 X
  * `dpkg`(Debian 계열)과 `rpm`(Red Hat 계열)이 있음.
* **고수준 패키지 관리 도구** (보통 사용됨): 패키지 간 의존성을 관리 도구가 스스로 파악하고 설치
  * `apt`, `apt-get`(Debian 계열)과 `yum`, `dnf`(Red Hat 계열)이 있음.

## apt & apt-get
* `apt-get`: 패키지의 설치, 업데이트 및 삭제만 가능 / 정밀한 명령에 용이
  * 설치 가능한 패키지 조회: `apt-cache` 사용
  * 설치된 패키지 조회: `dpkg -l` 사용
* `apt`: 위의 기능을 통합하여 수행 가능 / 덜 정밀하지만 사용이 편리

### 명령어
| 명령어 | 의미 / 기능 | 사용법 |
| :--- | :--- | :--- |
| **list** | 패키지 목록 출력 | `apt list` |
| **search** | 특정 패키지 검색 | `apt search [검색어]` |
| **show** | 특정 패키지의 상세 정보 확인 | `apt show [패키지명]` |
| **install** | 패키지 설치 | `apt install [패키지명]` |
| **reinstall** | 설치된 패키지 재설치 | `apt reinstall [패키지명]` |
| **remove** | 패키지 삭제 | `apt remove [패키지명]` |
| **update** | 패키지 목록(저장소) 업데이트 | `apt update` |
| **upgrade** | 설치된 모든 패키지 업그레이드 | `apt upgrade` |

### 옵션
| 옵션 | 의미 / 기능 |
| :--- | :--- |
| **-d** | 패키지를 다운로드만 하고 설치는 하지 않음 (`--download-only`) |
| **-y** | 설치 중 나타나는 모든 프롬프트에 자동으로 'yes' 응답 (`--yes`) |
| **--fix-missing** | 깨지거나 누락된 패키지 의존성을 복구 시도 |
| **--upgradable** | 업그레이드가 가능한 패키지 목록만 확인 (`apt list --upgradable` 형태로 사용) |
| **--only-upgrade** | 이미 설치되어 있는 패키지만 업그레이드 (새로운 패키지 설치 방지) |
| **--arch-only** | 특정 시스템 아키텍처에 맞는 패키지만 처리 |
| **--dry-run** | 실제로 설치/삭제하지 않고 실행 결과만 시뮬레이션하여 보여줌 |
| **--purge** | 패키지 삭제 시 설정 파일까지 완전히 제거 (`apt purge` 또는 `apt remove --purge`) |

## 네트워크
: 그물+일의 합성어로 2개 이상의 컴퓨터들이 서로 통신할 수 있도록 하기 위해 필요한 모든 것들을 통칭하는 표현
계층 구조를 가지고 있으며 각 계층은 자신의 바로 아래 계층과만 통신할 수 있음.
* **프로토콜**: 각 계층에서 사용하는 통신 규약
* 현대의 많은 프로그램들은 TCP/IP 프로토콜을 사용하고 있음

**OSI 7계층 구조**
1. 물리 계층 (Physical Layer)
2. 데이터 링크 계층 (Data Link Layer)
3. 네트워크 계층 (Network Layer)
4. 전송 계층 (Transport Layer)
5. 세션 계층 (Session Layer)
6. 표현 계층 (Presentation Layer)
7. 응용 계층 (Application Layer)

**관련 개념**
* **세션**: 수신자와 송신자 간 연결상태
* **세그먼트**: 전송 계층에서 송수신하는 데이터의 단위
* **패킷**: 네트워크 계층에서 송수신하는 데이터의 단위
* **프레임**: 데이터 링크 계층에서 송수신하는 데이터의 단위
* **MAC 주소**: 기기마다 고유한 주소. 송신자와 수신자를 식별함

---

### 네트워크 인터페이스
: 컴퓨터나 네트워크 장비가 통신하기 위한 물리적 or 가상의 연결 지점
* **네트워크 인터페이스 카드 (NIC)**: 컴퓨터가 네트워크와 통신할 수 있게 해주는 하드웨어 장치 -> LAN 혹은 Wifi에서 받은 전기 신호를 디지털 데이터로 변환
* **가상 랜카드**: 로컬 머신과 가상 머신을 연결함 (가상 머신을 사용한다면 생김)

**ifconfig 출력 정보 및 명령어**
| 항목 / 명령어 | 의미 / 기능 |
| :--- | :--- |
| **flags** | 인터페이스의 현재 상태 (UP, BROADCAST, RUNNING 등) |
| **mtu** | 네트워크를 통해 한 번에 전송할 수 있는 최대 데이터 크기 (Maximum Transmission Unit) |
| **inet** | IPv4 주소 |
| **netmask** | 서브넷 마스크 주소 |
| **broadcast** | 브로드캐스트 주소 |
| **ether** | MAC 주소 (물리적 하드웨어 주소) |
| **RX[ ]** | 수신(Receive)된 패킷 및 데이터 통계 |
| **TX[ ]** | 송신(Transmit)된 패킷 및 데이터 통계 |
| **ifconfig [이름] up** | 해당 네트워크 인터페이스를 활성화 |
| **ifconfig [이름] down** | 해당 네트워크 인터페이스를 비활성화 |

### 네트워크 접속 (nc)
`nc`: netcat의 줄임말로 TCP 혹은 UDP 연결을 읽거나 기록하는 프로그램
(드림핵의 포너블 문제를 nc로 접속 가능)
* 사용법: `nc [옵션] [ip] [port]`

| 옵션 | 의미 / 기능 |
| :--- | :--- |
| **-d** | 백그라운드로 실행하며 표준 입력(stdin)을 읽지 않음 |
| **-e** | 연결이 성립된 후 실행할 프로그램을 지정 (주로 셸 실행에 사용) |
| **-o** | 송수신된 데이터를 헥스 덤프(Hex dump) 형태로 지정한 파일에 기록 |
| **-p** | 접속을 대기하거나 연결할 로컬 포트 번호를 지정 |
| **-s** | 송신할 로컬 소스 IP 주소를 지정 |
| **-n** | 호스트명(도메인) 대신 IP 주소만 사용하며 DNS 이름 해석을 하지 않음 |
| **-u** | 기본값인 TCP 대신 UDP 프로토콜을 사용 |
| **-l** | 리슨(Listen) 모드로 동작하여 외부의 연결을 기다림 (서버 모드) |
| **-c** | 연결 시 지정된 셸 스크립트나 명령어를 실행 |
| **-v** | 상세 정보 출력 (Verbose 모드, 연결 상태 등을 자세히 확인 가능) |

---

### 네트워크 접속 (ssh)
`ssh`: 과거 리눅스에서 셸 원격 접속에 사용하던 텔넷이 암호화를 지원하지 않아 이를 보완하기 위해 나온 프로토콜
* 안전하게, 원격으로 셸 사용 가능
* 사용법: `ssh [옵션] [사용자 이름]@[서버 주소] [명령어]`

| 옵션 | 의미 / 기능 |
| :--- | :--- |
| **-p** | 원격 서버에 접속할 포트 번호를 지정 (ssh 기본 포트는 22) |
| **-v** | 접속 과정의 상세한 디버깅 메세지 출력 (Verbose) |
| **-i** | 공개키 인증 시 사용할 개인키 파일(Identity file)의 경로를 지정 |
| **-X** | X11 포워딩을 활성화하여 원격 서버의 GUI 프로그램을 로컬 화면에 띄움 |
| **-L** | 로컬 포트 포워딩 (로컬 포트를 원격지 포트로 터널링) |
| **-R** | 원격 포트 포워딩 (원격지 포트를 로컬 포트로 터널링) |
| **-C** | 송수신하는 모든 데이터를 압축하여 전송 속도를 높임 (Compression) |

### 파일 다운로드 (wget)
`wget`: 웹 상의 파일을 다운받기 위한 명령어
* HTTP, HTTPS, FTP 프로토콜을 사용하는 사이트의 파일들을 다운로드할 수 있다.
* 사용법: `wget [옵션] [URL]`

| 옵션 | 기능 |
| :--- | :--- |
| **-O [파일명]** | 다운로드한 파일의 파일명을 지정 |
| **--limit-rate=N** | 다운로드 시 속도를 제한 |
| **-b** | 백그라운드에서 다운로드 |
| **-d** | 디버그 내용을 출력 |
| **--reject=[확장자]** | 특정 확장자만 제외하고 다운로드 |
| **-r** | 재귀적으로 탐색하여 파일을 다운로드 |

### 네트워크 데이터 전송 (curl)
`curl`: client URL의 약자로 특정 프로토콜을 이용해 URL로 데이터를 전송
* 서버에 데이터를 보내거나 가져올 때 사용.
* HTTP, HTTPS, FTP, TELNET 등 다양한 프로토콜을 지원한다.
* 사용법: `curl [옵션] [URL]`

| 옵션 | 기능 |
| :--- | :--- |
| **-k** | HTTPS를 사용하는 경우 인증서에 대한 검증 없이 연결 |
| **-i** | HTTP 헤더 정보만 출력 |
| **-L** | HTTP 301, 302를 받은 경우 리다이렉션 URL로 이동 |
| **-d [데이터]** | HTTP POST 데이터를 전송 |
| **-o [파일 이름]** | curl로 받아온 내용을 파일로 저장 |
| **-X [메소드]** | 주어진 메소드(GET, POST, DELETE 등)로 요청 |
| **-A [이름]** | User-Agent 정보를 전송 |
| **-H [헤더]** | 전송 시 사용할 헤더 정보를 지정 |
| **-u [이름]:[암호]** | 접속 시 이름과 비밀번호가 필요한 경우 사용 |
