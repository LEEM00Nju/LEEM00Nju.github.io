======
Dreamhack의 Linux 101를 학습하고 정리해봤다. 처음 기초를 갈고 닦았는데 생각보다 어려웠다. 학습 내용을 정리하고 추가로 이해한 내용을 덧붙여 작성했다.

리눅스 환경 구축하기
------
먼저, 리눅스 환경을 구축했다. 나는 윈도우를 사용 중이라 강의의 **윈도우에서 VirtualBox를 이용하여 리눅스 환경 구축하기**부분을 보며 진행하였다. (참고로, WSL2를 설치하는 방법도 있었는데 설치에 원인을 모르는 오류에 막혀서 이 방법을 선택했다...) 

- 가상머신 (Virtual Machine, VM): 컴퓨터 안에서 또 하나의 컴퓨터를 에뮬레이션하는 소프트웨어
  - 하나의 운영체제 위에 다양한 운영 체제 환경을 구축할 수 있음
  - 여러 운영체제 환경 구축 가능
  - 독립된 환경 구축
  - 스냅샷 기능: 가상 머신 상태 저장, 필요할 때 빠르게 복원 가능 (오류 대처에 용이)


나는 Oracle VirtualBox를 다운 받았다. 사실 구축 자체는 학습자료나 검색해서 따라가면 되어서 내가 만난 오류랑 어떻게 해결했는지만 간략히 적어놓겠다.

> 가상 머신 부팅이 실패했습니다. 운영 체제가 없거나 부팅 순서가 잘못되었을 수도 있습니다. 운영 체제 설치 DVD를 마운트하면 문제를 해결할 수도 있습니다. ISO 파일을 선택하면 이 대화 상자를 닫은 후 마운트를 시도합니다.
이런 오류는 DVD 옆에 파일을 선택할 수 있는 란이 있는데 그냥 초기에 생성할 때 넣었던 iso 파일을 입력하니까 괜찮아졌다.

### 터미널

### 파일과 디렉터리
파일, 디렉터리는 리눅스에서 시스템의 중요한 구성 요소이다.
리눅스는 하드웨어 장치, 네트워크 소켓, 프로세스 정보같은 시스템 자원들을 모두 파일로 관리하고 디렉터리는 이러한 파일들을 체계적으로 구성하여 사용자가 쉽게 접근하고 관리할 수 있도록 도와준다.

#### 파일(file)
: 의미가 있는 정보를 모아둔 논리적인 단위 (종이 문서의 묶음을 말하는 파일에서 유래)
* `<파일이름>.<확장자명>`
* **확장자와 매직 넘버(Magic Number):**
  * GUI 환경에서는 확장자로 파일 종류를 보여주지만, CLI 환경에서는 큰 상관 X
  * 운영체제는 파일의 맨 처음 특정 바이트 단위(매직 넘버 또는 파일 시그니처)를 읽어 구분하므로 반드시 확장자명을 설정할 필요 X
  * 리눅스에서 확장자가 필수는 아니지만, 쉽게 구분하기 위해 관례적으로 `.sh`(셸 스크립트), `.log`(로그 파일) 등의 확장자를 붙여서 사용

<br>

#### 디렉터리(Directory)
: 파일을 분류하기 위해 사용하는 네임스페이스 (Windows 환경의 '폴더'와 동일한 개념)
* 상위 디렉터리와 하위 디렉터리가 존재
* 리눅스에서는 디렉터리 역시 특수한 형태의 '파일'로 취급하여 관리

<br>

#### 트리(Tree) 구조와 경로(Path)
일반적으로 리눅스의 디렉터리와 파일들은 나무(Tree) 형태의 계층 구조를 형성한다.

#### 디렉터리 표기법
| 표기 | 의미 |
| :--- | :--- |
| `/` | 최상위 디렉터리 |
| `/<directory 1>` | 최상위 디렉터리의 하위 디렉터리 |
| `/<directory 1>/<directory 2>` | `<directory 1>`의 하위 디렉터리 |

#### 절대 경로 vs 상대 경로
* **절대 경로:** 어떤 폴더나 디렉터리의 경로를 최상위 디렉터리(`/`)부터 끝까지 표시한 경로
* **상대 경로:** 경로가 최상위 디렉터리(`/`)부터 시작하지 않는 경우 (현재 위치 기준)
  * `./` : 현재 사용자가 위치한 디렉터리의 위치
  * `~/` : 사용자의 홈 디렉터리
  * `../` : 상위(부모) 디렉터리

> **주의) 커널 레벨에서의 파일과 디렉터리**
> 리눅스 커널은 내부적으로 파일과 디렉터리를 **같은 구조체를 사용하여 관리**한다. 
> 이 때문에 커널 레벨에서는 두 가지를 크게 구분하지 않고 모두 파일의 한 종류로 취급한다. 따라서 사용자는 **권한(Permission) 정보**를 보고 파일과 디렉터리를 구분해야 한다.

### 기초 명령어(Basic Commands)

| 명령어 | 의미 | 사용법 | 예시 |
| :--- | :--- | :--- | :--- |
| **sudo apt update** | 패키지 목록(저장소) 최신화 | `sudo apt update` | `sudo apt update` |
| **sudo apt upgrade** | 설치된 패키지 업그레이드 | `sudo apt upgrade` | `sudo apt upgrade` |
| **id** | 현재 사용자의 계정 및 그룹 정보 확인 | `id` | `id` |
| **pwd** | 현재 작업 중인 디렉토리(폴더) 절대 경로 출력 | `pwd` | `pwd` |
| **ls** | 현재 위치의 파일 및 디렉토리 목록 확인 | `ls [옵션] [경로]` | `ls -al` |
| **cd** | 다른 디렉토리로 이동 | `cd [이동할 경로]` | `cd /var/log` |
| **mkdir** | 새로운 디렉토리(폴더) 생성 | `mkdir [만들 디렉토리명]` | `mkdir test_folder` |
| **touch** | 빈 파일 생성 또는 파일의 시간 정보 수정 | `touch [만들 파일명]` | `touch new_file.txt` |
| **mv** | 파일/디렉토리 이동 또는 이름 변경 | `mv [원본] [목적지/새이름]` | `mv old.txt new.txt` |
| **rm** | 파일이나 디렉토리 삭제 | `rm [옵션] [삭제할 파일명]` | `rm -rf useless_folder` |
| **cat** | 파일의 내용을 화면에 출력 | `cat [읽을 파일명]` | `cat memo.txt` |
| **file** | 파일의 종류(타입) 확인 | `file [확인할 파일명]` | `file image.png` |
| **echo** | 입력한 텍스트나 변수를 화면에 출력 | `echo [출력할 문자열]` | `echo "Hello Linux!"` |
| **cp** | 파일이나 디렉토리 복사 | `cp [원본 파일] [복사될 위치/이름]` | `cp origin.txt copy.txt` |
| **grep** | 파일 내에서 특정 문자열 검색 | `grep [찾을 단어] [탐색할 파일명]` | `grep "error" log.txt` |
| **man** | 특정 명령어의 매뉴얼(도움말) 확인 | `man [궁금한 명령어]` | `man ls` |
| **curl** | 서버와 데이터 송수신 (웹페이지 소스 가져오기 등) | `curl [URL]` | `curl http://google.com` |

### 권한

**1. 유저와 그룹**
리눅스의 사용자 계정 정보는 보통 다음과 같은 형식으로 관리된다.
`[이름]:[암호]:[UID]:[GID]:[추가정보]:[홈 디렉터리 경로]:[기본 셸]`
* **유저 (User)**: 이름과 고유한 사용자 ID(UID)를 가짐
* **그룹 (Group)**: 여러 유저가 소속될 수 있는 그룹으로, 그룹 이름과 고유한 그룹 ID(GID)를 가짐
* **접근 제어**: 특정 파일이나 디렉토리에 유저가 접근하려고 하면, 시스템은 해당 유저의 UID와 유저가 속한 그룹의 GID를 확인하여 권한 보유 여부를 판단한 후 접근 제어

**2. 파일 및 디렉토리 권한**
* 리눅스의 각 파일 및 디렉토리는 **소유자(Owner)**와 **소유 그룹(Group)**을 가짐
* **권한의 종류**: 
  * **읽기(r)** / **쓰기(w)** / **실행(x)** 권한으로 나뉘며, 파일의 내용 접근과 실행 허용 여부를 결정함

**3. 권한 기호와 상태 표**

| 권한 | 상태 |
| :--- | :--- |
| -r-------- | 소유자에게 읽기 권한 |
| --w------- | 소유자에게 쓰기 권한 |
| ---x------ | 소유자에게 실행 권한 |
| ----r----- | 그룹에게 읽기 권한 |
| -----w---- | 그룹에게 쓰기 권한 |
| ------x--- | 그룹에게 실행 권한 |
| -------r-- | 다른 모든 사용자에게 읽기 권한 |
| --------w- | 다른 모든 사용자에게 쓰기 권한 |
| ---------x | 다른 모든 사용자에게 실행 권한 |


### 와일드카드(Wildcards)
> 리눅스에서 여러 파일이나 문자를 한 번에 지정할 때 사용하는 특수 문자이다.

| 명령어 | 의미 | 사용법 | 예시 |
| :--- | :--- | :--- | :--- |
| **?** | 임의의 **한 문자**를 대체 | `명령어 [문자]?` | `ls file?.txt`<br>*(file1.txt, fileA.txt 등 검색)* |
| **\*** | 길이 상관없이 **임의의 문자열**을 대체 | `명령어 [문자]*` | `ls *.txt`<br>*(.txt로 끝나는 모든 파일 검색)* |
| **[ ]** | 괄호 안의 **문자 중 하나**와 일치 | `명령어 [문자][범위]` | `ls file[1-3].txt`<br>*(file1, file2, file3 검색)* |


### 리다이렉션(Redirection)
: 명령어의 출력 결과를 화면이 아닌 파일로 보내거나, 파일의 내용을 명령어의 입력으로 받을 때 사용한다.

| 명령어 | 의미 | 사용법 | 예시 |
| :--- | :--- | :--- | :--- |
| **>** | 명령어 실행 결과를 파일에 저장 **(덮어쓰기)** | `명령어 > [저장할 파일명]` | `echo "hi" > test.txt`<br>*(기존 내용 지우고 hi 저장)* |
| **>>** | 명령어 실행 결과를 파일 끝에 추가 **(이어쓰기)** | `명령어 >> [저장할 파일명]` | `echo "hello" >> test.txt`<br>*(기존 내용 밑에 hello 추가)* |
| **<** | 파일의 내용을 명령어의 **입력으로 사용** | `명령어 < [입력받을 파일명]` | `cat < test.txt`<br>*(test.txt의 내용을 cat으로 읽음)* |

### 프로그램과 프로세스

**1. 프로세스의 정의**
* **프로세스 (Process)**: 컴퓨터에서 현재 실행되고 있는 프로그램

**2. 프로그램이 프로세스가 되는 과정**
* **프로그램**: 원래 하드디스크와 같은 저장장치에 '파일' 형태로 존재
* **실행 및 메모리 적재**: 사용자로부터 실행 명령을 받으면, 컴퓨터의 주기억장치인 RAM(메모리)으로 데이터를 불러와 작동하게 됨
* 즉, 메모리에 적재되어 **실행 상태가 된 프로그램**을 프로세스라고 부른다.

**3. 프로세스 개념을 알아야 하는 이유**
* 개발의 최종 목적은 만든 프로그램을 실행하여 사용자가 원하는 동작을 안정적으로 수행하게 하는 것입니다.
* 프로그램이 컴퓨터 내부에서 어떻게 프로세스로 생성되고 관리되는지 그 방식을 이해해야, 더 효율적이고 문제없는 프로그램을 만들거나 시스템을 관리할 수 있기 때문입니다.
